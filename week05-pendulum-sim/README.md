## 二、人机协同三反思

本节基于本实验的全部人机对话实录、控制台报错堆栈与自动化测试输出撰写。

### 反思一（意图定义）：四段式 Prompt 如何界定约束边界

#### 1. 我的四段式结构

| 段落 | 回答的问题 | 本次实验中的例子（单摆任务原文） |
| :--- | :--- | :--- |
| **角色** | 让 AI 用什么身份和标准思考 | "你是一位资深前端可视化与物理仿真工程师" |
| **目标** | 一句话说清要什么 | "创建单个完整的 index.html，实现带物理简谐振动的单摆模拟器" |
| **技术约束** | 边界在哪：技术栈、量化参数、视觉、负向红线 | "纯原生 HTML5 Canvas，不引用外部库；背景 #1a1a24，摆球微弱发光；L=200px、g=9.8、初始摆角 45°；requestAnimationFrame 驱动" |
| **验收标准** | 怎样算完成（必须可判定） | "浏览器双击打开即可流畅左右摆动"、"控制台 0 报错" |

#### 2. 约束边界的三种作用

1. **量化参数防自由发挥**：`L=200px、g=9.8、45°` 不是装饰，它们直接决定动画量级——但像素与米之间还差一个比例尺（100px = 1m），若不点明，按原始数值算出的周期约 28 秒，像慢动作；补上比例尺后周期 2.84 秒，才符合真实单摆观感。
2. **负向红线防破坏**（增量任务中尤为重要）："仅做局部增量修改，勿破坏 Canvas 渲染"、"不引用外部库"，约束了 AI 在既有代码上的动刀范围。
3. **验收标准给出可判定的终点**："刷新后参数完美恢复""双摆翻转流畅无数值发散"都是能当场证伪的句子；而"做得好看"无法验收，只会换来一段无法收场的对话。

#### 3. 边界之外的空白，靠"提问—拍板"补上

四段式无法覆盖全部意图。AI 在歧义处主动发问，我逐次拍板：

- 目录名 `weeke5_pendulum_sim` 疑似多打了一个 e——确认后统一为 `week05-pendulum-sim`；
- "当前工作区"指课程仓库还是桌面文件夹——确认放入 `week05-pendulum-sim/`；
- 恢复出厂的默认角：从 45° 改为 120°（原因见反思二）。

**小结：意图边界是给 AI 画的"自由圈"。圈太大，AI 会替你猜（猜错就是返工）；圈太细，又浪费了它的专业发挥。这场实验真正练习的，是画圈的精度。**

### 反思二（排错自愈）：用客观证据引导 AI 修复

#### 1. 主案例：从控制台堆栈到规范修复

**现象**：点击"重置摆动"按钮后单摆停止运动，控制台报红。

**证据**（原样交给 AI 的控制台堆栈）：

```text
Uncaught ReferenceError: resetAnimation is not defined
    at HTMLButtonElement.onclick (index.html:68:15)
```

**引导修复的过程**：

1. AI 没有直接开修，而是先**复核证据**：全盘搜索工作区，发现仅有一个 index.html，且其中不存在 `onclick` 属性、也不存在 `resetAnimation` 函数——说明报错来自被改动过的旧副本；但该错误类型本身值得根治。
2. AI 判断这是**作用域断裂**的典型模式：内联 `onclick` 在全局作用域执行，而函数若定义在 `(function(){...})()` 闭包内，全局看不到它 → ReferenceError → 点击事件当场中断，重置逻辑一行都不会执行。
3. 用**最小复现**验证判断（Node 实测）：

```text
BUG REPRO -> ReferenceError: resetAnimation is not defined   ← 全局作用域调用闭包函数
FIXED     -> resetAnimation 正常工作                          ← 同作用域绑定后调用
```

4. **规范修法**：把匿名回调提炼为具名函数 `resetAnimation`，并在其所在作用域内用 `addEventListener` 绑定（而不是把函数暴露到全局去迁就内联写法）。
5. **回归验证**：13/13 项自动化检查通过，含复位精度、拖拽联动、0 报错。

#### 2. 过程中另外三个问题（同样靠证据链暴露并修复）

| 问题 | 证据 | 修复 |
| :--- | :--- | :--- |
| 加载即黑屏的隐患：`resize()` 在 `trail` 声明之前被调用（暂时性死区 TDZ） | 代码走查时发现调用顺序与声明顺序矛盾 | 调整声明顺序，先声明后调用 |
| 拖拽读数延迟：物理状态已即时更新，但 HUD 文字要等下一帧才刷新 | 测试断言暴露：期望 `45.0° / 90.0°`，实得 `45.0° / 45.0°` | 增加 `updateReadout()` 在拖拽与复位时即时刷新 |
| 物理目标未达成："双摆翻转"验收项失败 | 60 秒仿真实测 max\|θ₂\| = 56.4°，能量估算 ≈17 J 不足以越过翻转势垒 | 默认释放角 45° → 120°（E = 88.2 J），重测 max\|θ₂\| = 1191.7°（约 3.3 圈完整翻转） |

#### 3. 我总结的自愈闭环

**捕获（控制台/测试）→ 复现（最小案例）→ 定位（证据指向）→ 修复（规范模式）→ 回归（全套测试）。**

AI 在这个闭环里是高效的执行器，但"什么算失败、证据是否充分、修复是否接受"的裁判权在人手里。不给证据只说"报错了"，AI 只能猜；给出堆栈三要素（错误类型、消息、位置），修复就有了方向。

### 反思三（主体协同）：AI 与我各自不可替代的核心价值

#### 1. AI 不可替代的价值

- **速度**：5 秒写出可运行代码；
- **广度**：从双摆拉格朗日方程、RK4 数值积分、Canvas 渲染到自动化测试，一次成型跨领域实现；
- **耐心与精度**：240 Hz 定步长仿真、60 秒能量漂移实测 0.0000 J、27 项回归检查不厌其烦；
- **规范一致性**：中文注释、命名风格、文档结构始终统一。

#### 2. 我不可替代的价值

- **出题权**：选题（双摆而非单摆）、验收定义（"翻转流畅"而非"能动就行"）——AI 只会填空，出题的是我；
- **物理正确性判断**：45° 释放能量不足、太空 g=0 的失重表现、阻尼标定是否"自然"，这些判断依赖物理直觉而非代码能力；
- **品味与取舍**：`#1a1a24` 深色质感、彩虹拖尾、胶囊按钮的交互反馈，是审美层面的决定；
- **授权与责任**：哪些内容公开到 GitHub、以什么身份提交、是否接受 AI 的方案——最终签字盖章的是我；
- **必要的人工动作**：浏览器里的 GitHub 授权、肉眼验收、F5 强刷排除缓存——AI 替我完成不了。

#### 3. 一个诚实的观察

AI 也会犯错：TDZ 顺序缺陷、HUD 刷新延迟、45° 参数的物理误判、需要被确认的 "weeke5" 笔误、通用占位目录与课程真实内容的偏差。**这恰恰证明：验收权必须且只能在人手里。** 人机协同不是"AI 干活、人挂名"，而是"AI 生成候选方案集合，人负责判断、取舍并签字"。

commit 历史与这份反思一起，构成"我主导、AI 执行"的可审计台账——这也回答了实验考核为什么以三反思为核心：**代码是商品，可再生成；意图、排错逻辑与价值判断才是不可替代的创造。**

### 最大的收获

从"向 AI 许愿"到"向 AI 下达可验收的工程合同"——这大概是这门课里，比单摆、双摆本身更重要的东西。

## 三、进阶挑战（选做）：扩展功能说明

基线要求为"单摆简谐振动 + 滑块 + 复位"，本实验在基线上额外完成：

1. **RK4 高阶数值积分**（替代一阶欧拉/闭式解）：对混沌系统的长期演化稳定性至关重要，60 秒仿真能量漂移 0.0000 J，无数值发散；
2. **双摆混沌动力学**：完整实现拉格朗日方程，实测下摆 60 秒累计翻转约 3.3 圈；
3. **彩虹渐变衰减拖尾**：色相随时间流动 + 透明度随点龄二次衰减 + 叠加发光合成；
4. **天体场景系统**：四个预设 + 指数平滑过渡 + 滑块/标签/HUD 全链路同步 + 激活态胶囊高亮；
5. **localStorage 持久化**：参数变更即存、刷新自动恢复（含范围校验与隐私模式容错）；
6. **移动端适配**：Pointer Events 统一鼠标/触屏、命中半径自适应、响应式面板、面板高度动态避让；
7. **自动化回归测试**：27 项断言覆盖物理守恒、过渡平滑、持久化、拖拽与复位，全绿通过。
